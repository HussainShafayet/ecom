# Components & UI/Styling Conventions — `src/components/`

## Styling conventions

`tailwind.config.js` is almost stock default Tailwind — `content` scans `src/**/*.{js,jsx,ts,tsx}`, and the only `theme.extend` is an unused `spinning-cube` keyframe/animation (zero usages anywhere in `src` — dead config). There are **no custom color tokens, spacing scale, fonts, or design-system primitives** defined; every component uses raw Tailwind utility classes with hardcoded palette values (`blue-500`, `green-500`, `red-500`, `gray-700`, etc.) chosen ad hoc per component rather than semantic tokens. `src/tailwind.css` is just the three `@tailwind` directives. `src/index.css` is generic boilerplate (font stack only). `src/App.css` holds two global custom-CSS additions used repeatedly: removing number-input spinners, and a `.scrollbar-custom` gradient scrollbar class (used in `Layout.js`). `BackToTop` is the one component that breaks from Tailwind entirely, using CSS Modules (`BackToTop.module.css`) with hardcoded hex colors (`#4299e1`) instead of Tailwind's `blue-500`. `GlobalErrorHandler.js` mixes in full inline `style={{...}}` objects instead of Tailwind (the only fully inline-styled component), while `Slider.js` and `SelectFilter.js` use small inline `style` only for dynamic values (progress width, swatch hex color) alongside Tailwind classes — reasonable, not systemic. Layout containers repeat `"container mx-auto"` manually (13 occurrences) with no centralized `Container` component. Loading states consistently use `animate-pulse` gray-box skeletons (Tailwind's built-in utility), not a skeleton library.

## `common/` (top-level)

- **BackToTop.js** — floating scroll-to-top button with a circular SVG progress ring; prop: `scrollContainerRef`; CSS Modules, not Tailwind.
- **BottomNav.js** — mobile-only (`md:hidden`) bottom tab bar (Home/Shop/Cart/Wishlist/Account); reads Redux cart/auth state directly, no props.
- **Button.js** — generic button; props: `label`, `onClick`, `type` (default `"button"`), `styleClass` (extra classes appended); hardcoded blue background, no `variant`/`color` prop.
- **ErrorDisplay.js** — red bordered box listing an `errors` array prop; returns `null` if empty.
- **Field.js** (`Field`, `controlClass`, `describedBy`) — a form field with its label ABOVE it (a placeholder disappears when you type), an optional `hint`, and its problem under it (`role="alert"`, `id=<id>-error`); `controlClass(hasError, tall)` is the 48 px / 16 px-text control style (16 px: a phone zooms into anything smaller when focused). Used by checkout, sign in, sign up and the code page (it lived in `components/checkout/` first).
- **PhoneInput.js** — the phone box of every form: a fixed `+880` and a box for the digits (`type=tel`, `inputMode=numeric`, `autocomplete=tel-national`); hands `onChange` the DIGITS, already cleaned by `normalizePhone` (`01712345678`, `8801712345678`, a pasted `+880 1712-345678` all arrive as `1712345678`). `utils/phone.js`: `PHONE_PREFIX`, `normalizePhone`, `validatePhone` (the backend's rule: `+880` + exactly 10 digits), `maskPhone` (`+880 17•••••678`).
- **OtpInput.js** — the SMS code as one square per digit over ONE real, invisible input (`opacity-0`, lying over the boxes): the phone's number keypad and "fill in from SMS" (`one-time-code`), paste and backspace work, a screen reader reads the input, a tap on a box focuses it; the boxes are `aria-hidden`, the next empty one is lit while focused, all turn red on an error. `onChange` gets the digits (at most `length`, 6 unless the caller says otherwise: `VerifyOtp` passes the backend's `length`).
- **AuthLayout.js** — the frame of sign in / sign up / code, and the shop's own: a band in the site's blue-to-purple with the SHOP's logo, name and tagline from `state.site.site` (the bundled logo and "Welcome" until they arrive; works without a site slice), the two steps "Your phone" / "Your code" (`<ol aria-label="Steps">`, `aria-current="step"`, a ✓ on the finished one), the card overlapping the band with a round icon badge on its edge (`icon` prop), and "No password to remember" / "We never share your number" under it. Everything is drawn with CSS: the old sign-in put a brand panel with a picture from flaticon.com above the form and used a 30 %-white glass card.
- **LazySection.js** — a part of a long page that is mounted (so fetches) only when the customer is about to reach it: `useInView` (`hooks/useInView.js`) watches a wrapper `div` with an `IntersectionObserver` whose `root` is the nearest scrolling ancestor (the shop scrolls inside `Layout`'s own box, not the window, and an observer with no `root` cannot look ahead beyond a scroll box its target sits in) and whose `rootMargin` is 400 px ahead; a `SectionSkeleton` holds the place until then; once shown it stays (the observer disconnects). Where there is no `IntersectionObserver` (jsdom, very old browsers) it shows the content at once. Used by `Home` for the four sections below the first screen.
- **SectionError.js** — the card a part of a page shows in place of itself when it could not load: "We couldn't load this.", the sentence (`message`) and **Try again** (`onRetry`) or, without `onRetry`, **Reload page**. `role="alert"`.
- **Toaster.js** — the toasts of `toastSlice` stacked at the bottom of the screen (`bottom-36` = 144 px on a phone: above the bottom nav AND the fixed buy/checkout bar of the product and cart pages; `lg:bottom-6`): `role="alert"` for errors, `status` otherwise, a dismiss button each; draws nothing without toasts and tolerates a store without the slice. Drawn by `Layout`. (This replaces `GlobalErrorHandler`, the full-page error overlay, which is gone.)
- **WaitNotice.js** — the amber `role="alert"` box for a 429 ("You have asked for too many codes. Please try again in **25 minutes**"; `seconds` counts down, `formatWait` says it, a screen reader hears "a little while" instead of a number that changes every second). Sign in, sign up and the code page draw it while `hooks/useCountdown` is above 0 and disable the button ("Try again in 15 seconds") until then.
- **InputField.js** — labeled text input; props: `label`, `value`, `onChange`, `type`, `className`, `...rest`. Note: `className` is applied to both the wrapper `div` and the `<input>` — likely unintended duplication.
- **Loader.js** — small inline spinner + `message` prop (default `"Loading"`).
- **ProtectedRoute.js** — route guard using `react-router`'s `Outlet`; redirects to `/signin` if `!isAuthenticated`.
- **RichTextToHTML.js** — renders a `content` prop via `dangerouslySetInnerHTML`, in a wrapper that keeps admin-written content readable on a phone (pictures `max-w-full`, a wide table scrolls sideways, long words break) (XSS risk if the content isn't sanitized upstream by the backend — worth a security review before trusting this with user-generated content).
- **ScrollToTop.js** — no-render effect component; scrolls `scrollContainerRef` to top on route change.
- **SearchDropdown.js** — debounced (lodash, 1000ms) product search-suggestions dropdown with keyboard nav; pulls from the Redux `product` slice.
- **Slider.js** — Swiper-based hero image carousel; prop `image_sliders` (draws nothing without slides). Each slide is one `ContentLink` (`object-cover`, real `alt` from the caption); a slide with a `caption` shows it as the headline over a bottom gradient with a **Shop Now** button. Fade, autoplay every 5 s that pauses while the pointer is over it (`pauseOnMouseEnter`) and is off for a single slide or `prefers-reduced-motion`, `loop` only with several slides, pagination dots, round prev/next arrows (labelled, computer-width hover only, phones swipe), the first image `eager` + `fetchPriority=high` (LCP).
- **ContentLink.js** — where a CMS slide/banner/video leads (`resolveContentLink(item)` is exported): `type: product` → `/products/detail/<link>`, `category` → `/products/?category=<link>` (both a `<Link>`, same tab), otherwise an `http(s)` `external_link` → `<a target="_blank" rel="noopener noreferrer">`; anything else (a `javascript:` address, no link) is drawn as a plain `div`, not a broken link. Replaced the five copies of `getLink`, which sent an external address into `<Link to>` (where it never opened) and the hero tiles always to `/products/detail/<link>`.
- **SuccessMessage.js** — green bordered box for a `message` prop; mirrors `ErrorDisplay`'s styling pattern.
- **common/index.js** — barrel file re-exporting all of the above plus the `product/` subfolder components.

Also in `common/`: **SectionHeader.js** (the title row every homepage section shares: `title`, optional `subtitle`, and a "View All" `<Link>` to `to` in the same tab; no link without `to`; an optional `extra` node under the subtitle, which `ProductSection` passes through: the flash sale's countdown) and **ProductSection.js** (`SectionHeader` + a list of `ProductCard`s: props `title`, `subtitle`, `to`, `products`, `carousel`, `className`; draws nothing without products; a plain `grid-cols-2 sm:grid-cols-3 lg:grid-cols-6` grid by default, and with `carousel` a snap-scrolling swipe row on a phone that becomes that same grid from `md` up), and **SocialLinks.js** (icon links for `site.social_links`, for the platforms `facebook, instagram, x, youtube, linkedin, tiktok, whatsapp, telegram`; an unknown platform or a non-`http(s)` address is not drawn).

## `common/product/`

- **Breadcrum.js** — auto-generated breadcrumb from `location.pathname`. Filename is misspelled `Breadcrum.js` but the component (and its default export, imported as `Breadcrum`) is named `Breadcrumb` — a file/component naming inconsistency.
- **`ProductCard .js`** — filename genuinely contains a trailing space before the extension (verified with `ls -la`), and `common/index.js` imports it as `'./product/ProductCard '` (the literal space is in the import path too). Component: full product tile, wrapped in `React.memo`; props `product`, `cardForTrending`. Square image (falls back to `assets/images/default_product_image.jpg` when there is none or it fails), `NN% OFF` / `৳NN OFF` badge (`discountLabel`), brand, name (2 lines), an honest rating (stars rounded to the nearest half + the exact average and review count, nothing for an unrated product), price in taka (`formatPrice`: `৳3,579`, `৳881.10`) with the old price struck through. No view/order counters. Actions are always ONE `h-9` row so prices and buttons line up across a row of cards whatever each card's state: **Add to Cart** (primary) beside **Buy Now** (add, then `/checkout`; always just a ⚡ icon with a `title`/screen-reader label, because a card's width depends on its grid (2-6 columns, with or without a sidebar), not on the screen, and a label made "Add to Cart" wrap); a product with variants gets one **Choose Options** button to its page instead; out of stock shows an "Out of Stock" pill of the same height and a greyed image. A product's minimum order (`minimum_order_quantity` > 1) is a "Minimum order: N" badge over the image, deliberately not a line under the buttons (that made the card taller and the buttons of a row stop lining up); Add to Cart / Buy Now put N in the cart. The wishlist heart is a labelled `<button aria-pressed>`; for a signed-in customer it fills only when the shop took it, and a refusal (the backend's sentence, else "Could not add this to your wishlist") or a failed removal is a toast (it used to be a section error nothing displayed, or a `console.error`); a guest's wishlist is local and cannot fail. The wishlist page's **Clear Wishlist** is a real button; if the server could not clear a signed-in customer's list it says so and refetches what is still there. Busy state is **per card** (`Adding...`), so one card talking to the server never disables the others (the global `cart.cartLoading` is no longer read here). The small parts (`DiscountBadge`, `Rating`, `Price`, ...) live at module level: declared inside the component they would remount every render.
- **RatingStars.js** — five stars rounded to the nearest half (4.1 is four stars), the exact average and `(reviews)`; one `role="img"` with `aria-label="Rated 4.3 out of 5 from 12 reviews"`. Props `rating`, `reviews`, `iconClass`, `className`. Used by `ProductCard` and the product page (both used `Math.ceil`, so 4.1 drew five stars).
- **ProductGallery.js** — the product page's pictures/videos, phone first: a full-width square Swiper (`initialSlide`, remounted per colour via a key of the file URLs), a "2/5" counter, and a row of 56 px thumbnail buttons under it. A thumbnail is always a picture (`thumbnail_url`, a play icon on a video), never a `<video>`; a video in the slider is `preload="none"` with its thumbnail as `poster`, so it downloads only when played. A picture zooms on tap (`react-medium-image-zoom`; needs `ResizeObserver`). Props `media`, `selected`, `onSelect(item)` (thumbnail tap or swipe), `name`. Falls back to the default image.
- **ProductOptions.js** — colour swatches (40 px, `aria-label`/`aria-pressed`) and size chips (`min-h-10`), the chosen names written out ("Color: Red", a phone has no tooltip); the sizes offered are the chosen colour's, else the product's; a sold-out size is struck through but selectable.
- **QuantitySelector.js** — − / typed number / + (40 px targets, `inputMode=numeric`); every valid number goes to `onChange`, the box shows what the owner kept (`productSlice.setQuantity` on the product page, the cart line's update in the cart; both clamp between the minimum order and `MAX_QUANTITY` 10000). Props `quantity`, `minimum`, `onChange`, `label` (default "Quantity", `null` hides it), `showMinimum` (default true: "Minimum order: N" under it when N > 1; the cart line says it itself), `name` ("Quantity of Mug", "Decrease quantity of Mug" for screen readers).
- **PurchaseBar.js** — the buy buttons: on a phone a bar fixed to the bottom just above the bottom nav (`bottom-14`, z-40) with the price, Add to Cart and Buy Now; from `md` an ordinary row (`md:static`, price hidden). Add to Cart becomes a "✓ Added · View cart" link for 4 s after it worked; a `message` (why the shop refused: stock...) is written inside the bar, where the customer is looking; `canBuy` false shows "Out of Stock".
- **CollapsibleSection.js** — a titled block that folds up under a 48 px title button on a phone (`aria-expanded`), always open from `md` (the title is inert there).
- **ShareMenu.js** — `navigator.share` sheet where the browser has one (phones over https); otherwise a menu: Copy link ("Link copied", falls back to `execCommand` without the Clipboard API, e.g. a page opened over plain http), Facebook, X, WhatsApp, all with the product's `name` (they used `product.title`, which does not exist, and `alert()`ed).
- **RatingAndReview.js** — product-detail reviews list + review submission form (rating, comment, file/video upload); prop `product`. When the signed-in customer can not review, a file-local `ReviewEligibility` says why from `review_status`: `reviewed` ("use the edit icon"), `waiting_for_delivery` ("once your order has been delivered" + a *View my order* link to `/orders/{review_order_id}`), anything else the general rule. Minor bug: `dispatch(dispatch(updateReviewFormData(...)))` — a double-dispatch nesting around lines ~82–85, likely a copy-paste error.

## `products/`

The filters of the products page (see `pages/Products` in [02-routing-pages.md](02-routing-pages.md)). Everything is controlled: the panel edits a `filters` object (`{category, brands, tags, colors, sizes, min_price, max_price, discount_type, discount_value}`, see `utils/productFilters`) and hands each change to `onChange`.

- **FilterPanel.js** — every group, one under another: Category (`CategoryTree`), Price (`PriceFilter`), Brand / Tag (`CheckList`: 48 px rows whose whole row is the `<label>`, the first 8 and "Show all N" / "Show fewer", what is chosen always shown), Color / Size (`Chip`: 44 px, `aria-pressed`), Discount (radios, "Any" first). It reads the shop's lists from `state.content` and draws `SidebarSkeleton` until they arrived or `SectionError` + Try again (`fetchShopContent`) if they could not. Prop `commitPrice`: `'change'` (every key, for the sheet's draft) or `'blur'` (on leaving the box / Enter, for the sidebar).
- **FilterSection.js** — a group that opens and closes: a 48 px heading button with `aria-expanded`/`aria-controls` and the number chosen in it; `defaultOpen` is read once. Replaced `common/Accordion`.
- **CategoryTree.js** — the categories as a tree with no scroll box; choosing one chooses it and what is under it (the backend's `category` includes children), choosing it again takes it off; a 44 px chevron opens the children, the path down to the chosen one starts open. `CategoryNode` is declared at module level (a component declared in a render forgets what it opened).
- **PriceFilter.js** — From / To, `inputmode="numeric"`, digits only, ৳ in front; the wrong-way-round sentence comes from its own boxes, so it shows on the desktop too where nothing is applied until it is right; the shop's price range as a hint.
- **FilterSheet.js** — the phone's sheet: `role="dialog" aria-modal`, `fixed inset-0 z-[60] lg:hidden`, `max-h-[90vh]` (`90dvh` where supported), a header with a 44 px X, the groups scrolling in the middle, and **Clear all** / **Show results** in a footer that never scrolls away (`env(safe-area-inset-bottom)`). `useDialog` (`hooks/useDialog.js`) gives it focus in and out, Tab inside, Esc, and stops the page behind it from scrolling (`scrollRef`, the Layout's scroll box, gets `overflow: hidden` while it is open). Show results with a range the wrong way round focuses the From box instead.
- **FilterSidebar.js** — the same panel for `lg`: a sticky card with the heading and Clear all.
- **ActiveFilters.js** — the chip row (`role="group"`, every chip a button "Remove Acme"), nothing when nothing is chosen.
- **products/index.js** — barrel.

## `common/skeleton/`

Consistent pattern: plain functional components using Tailwind's `animate-pulse` + gray placeholder `div`s (no external skeleton library). Barrel-exported via `skeleton/index.js`: `HeroSectionSkeleton`, `ProductCardSkeleton`, `SectionSkeleton` (used generically by Flash Sale/Best Selling/New Arrival/Featured/AllProducts, toggled via `forRoute`; note its internal component is misspelled `Sectionkeleton`, though the export/usage is unaffected), `ProductDetailsSkeleton` (same shape as the page: square gallery + thumbnails, details, sections), `ProductsPageSkeleton` (just the cards, two to a row: the products page keeps its title and controls on the screen while a list loads), `SidebarSkeleton` (the filter groups in the panel's shape: a heading and some rows each), `ProfileSkeleton` (the band with the picture on its edge, the orders row, the tabs, the details), `CartSkeleton` (same shape as the cart page, no scroll box), `CheckoutSkeleton`, `OrdersSkeleton` (three order cards) and `OrderDetailSkeleton` (header, progress, items; also the tracking lookup).

## `sections/` (homepage/shop sections, all Redux-driven)

- **HeroSection.js** — top banner; needs the `content` slice (`image_sliders`, `video_sliders`, `left_banner`, `right_banner`). A phone gets the `Slider` at 16:9 (`sm` 2:1) and the promo tiles in a 2-column row; a computer (`lg`) gets a 380 px row: the slider over 2/3, beside it the video (`controls`, muted, looped, prev/next buttons and a caption pill when there are several) above the tiles (or the tiles stacked when there is no video). **Video is computer-only** (`useMediaQuery('(min-width: 1024px)')` decides whether the `<video>` is mounted at all, so a phone never downloads it, and a right banner that is a video is not drawn on a phone). Tiles are `ContentLink`s with `object-cover` images (a video tile on a computer); the whole hero draws nothing when the admin left everything empty. `HeroSectionSkeleton` has the same grid so nothing jumps when it loads.
- **CategoryStrip.js** — the first thing under the hero: one row of the first 12 categories (`fetchAllCategories({page:1, page_size:12})`), each a round picture + name linking to `/products/?category=<slug>` (default image when none; the picture is decoration, the name is the label), a category with a discount carries a small red pill (`discountLabel`), then an **All** tile to `/categories`. A row you swipe on a phone (scrollbar hidden), spread across on `lg`; `<nav aria-label="Shop by category">`; round skeleton while loading, nothing when there are no categories or they failed to load. (This replaced the "Shop by Category" banner grid `CategoriesSection` and its `CategorySectionSkeleton`, which showed the same categories a second time further down.)
- **FlashSaleCountdown.js** — the flash sale's pill (red-to-orange, ⚡): `endsAt` (a moment on this device's clock), `label` ("Ends in" / "Starts in"), `onEnd` (called once when it reaches zero). `role="timer"` with an `aria-label` in words ("Flash sale ends in 2 hours 14 minutes": `utils/flashSale.spokenTime`), the changing digits `aria-hidden` and `tabular-nums` so nothing jumps; "2d 05:14:09" from a day up (`formatCountdown`). Drawn by `useCountdownTo` (`hooks/useCountdownTo.js`), which works out the time left from the clock at every tick, on the second, and again when a sleeping tab becomes visible (a counter that subtracts one a second is wrong after a phone slept).
- **FlashSale.js** — flash-sale banner + `ProductSection` (its `extra` is the countdown while `flash_window` is live with an end; on its own page, with no products and a window that is not live, a `NotLiveNotice`: "has ended" or "has not started yet" with a "Starts in" countdown); prop `forRoute` (toggles hero-style banner + a second "Recommended Products" `ProductSection` of the same products, and swaps the homepage swipe row + "View All" for a plain grid); needs `flash_sale` + `content` slices.
- **BestSelling.js** — same pattern for best-sellers; needs `best_selling` + `content` slices.
- **NewArrival.js** — same pattern for new arrivals; needs `new_arrival` + `content` slices.
- **FeaturedProducts.js** — same pattern for featured products; needs `product.featured` + `content` slices.
- **AllProducts.js** — "All Products" `ProductSection` (grid) linking to `/products`, then a **Load more** button that adds the next page (12) under the products already there without leaving the page (`fetchAllProducts({page, page_size: 12})` appends for `page > 1`; hidden when the slice's `hasMore` is false). While the next page loads the products stay (a skeleton or an error card replaces the section only when there is nothing to show); a failed "Load more" says so under the products and the same button tries again. Needs the `product` slice, which the `/products` page shares.
- **Testomonials.js** — static/hardcoded customer testimonials (demo data with `placeholder.com` photo URLs, not Redux-backed); internally named `Testimonials` (correct spelling) but the file is misspelled `Testomonials.js`, and it's imported-but-commented-out in `src/pages/Home.js` — effectively dead/unused.
- **RecentlyViewed.js** — homepage-only swipe row/grid (`ProductSection` with `carousel`) of the shopper's own recently-viewed products, drawn by `Home` after `FeaturedProducts` and before `AllProducts`; needs the `recentlyViewed` slice ([01-state-management.md](01-state-management.md)); no `forRoute` prop, no "View All" link (no such route), no skeleton (the data is local and synchronous); draws nothing when the list is empty.

`FlashSale`/`BestSelling`/`NewArrival`/`FeaturedProducts` still share the duplicated `forRoute` banner block (image slider + right banner/video, ~50 lines each), but their product lists are now one shared `ProductSection` (title row + cards; "View All" link and homepage swipe row only when not `forRoute`) — the banner block is the remaining candidate for extraction into one shared component.

## `orders/`

Shared by `Orders`, `OrderDetail`, `OrderConfirmation` and `OrderTracking`.

- **OrderStatusBadge.js** — coloured pill for a status (`status` picks the colour, `label` is the backend's `status_display`; an unknown status is grey). The backend's statuses: `pending, confirmed, paid, shipped, delivered, returned, cancelled, refunded`.
- **OrderTimeline.js** — progress from the backend's `history` (`[{status, status_display, created_at}]`): placed → (confirmed, only if staff confirmed) → (paid, only if it happened) → shipped → delivered, unreached steps grey ("Not yet"); an order that ended without delivery (cancelled, a parcel that came back = returned, or refunded) ends in a red step and drops the steps that never happened. Drawn SMALL as an `<ol aria-label="Order progress">`: a dot (32 px) per step on a line, stacked on a phone (the items are not pushed out of the first screen; it used to be one big card per step), a row from `md`; the newest step that happened has `aria-current="step"` and a ring.
- **OrderItems.js** — the order's lines (picture, name cut at two lines, variant, quantity × unit price, line total); a line whose product still exists is ONE link (the whole row, at least 72 px, opens the product) with the picture as decoration (`alt=""`).
